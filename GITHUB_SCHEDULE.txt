================================================================================
DATAPILOT — GITHUB PUSH SCHEDULE (Day-by-Day)
================================================================================
Goal     : Push the whole project to GitHub in small, clean, reviewable chunks.
Assumption: All code is already written. This plan tells you WHAT to stage,
            WHAT message to commit, and in what ORDER — using conventional
            commit messages (feat/fix/docs/refactor/test/ci/chore).

Rules
-----
1. Run steps top-to-bottom inside each day. Commands run in the project root.
2. One commit per box. Do NOT merge steps.
3. Files are staged with explicit paths — never `git add -A` unless a step says so.
4. `.env` is gitignored; your API key never gets pushed.

------------------------------------------------------------------------------------------
DAY 1 — PROJECT FOUNDATION & ENVIRONMENT
------------------------------------------------------------------------------------------
Goal: Create the repo, the scaffold files, and the very first commits.

Step 1.1  Initialize the repository (one-time, do first)
--------------------------------------------------------
  git init
  git branch -M main

Step 1.2  Scaffold metadata
--------------------------------------------------------
  git add .gitignore requirements.txt LICENSE README.md .env.example
  git commit -m "chore: bootstrap project scaffold (ignore rules, deps, license, env template)"

Step 1.3  First cut of documentation
--------------------------------------------------------
  git add GUIDE.md PROJECT_DOCUMENTATION.md
  git commit -m "docs: add getting-started guide and full project documentation"

Step 1.4  Streamlit theme configuration
--------------------------------------------------------
  git add .streamlit/config.toml
  git commit -m "feat(ui): add custom streamlit dark theme"

DAY 9 — PUSH & VERIFY ON GITHUB (optional stretch, only if you want history staged now)
------------------------------------------------------------------------------------------
Goal: Publish the repository and confirm CI-less basics.

Step 9.1  Create the remote (do once via https://github.com/new)
Step 9.2  Push everything
--------------------------------------------------------
  git remote add origin https://github.com/USERNAME/datapilot.git
  git push -u origin main
  git push --tags

Step 9.3  Confirm
--------------------------------------------------------
  - Open the repo URL and check the commits appear day-by-day.
  - Confirm data/processed/, reports/, .env are NOT in the repo.
