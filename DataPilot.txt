The most important architectural principle

LLM ≠ Data Processing Engine

Don't let the model directly clean millions of rows.

Instead:

                 DATA
                  │
                  ▼
        Deterministic Processing
        Pandas / DuckDB / Rules
                  │
                  ▼
             Metadata
                  │
                  ▼
             7–9B LLM
                  │
                  ▼
        Reasoning / Explanation
        Recommendation / Mapping
                  │
                  ▼
        Deterministic Execution

This makes the project much more technically credible.

2. What the 7–9B model actually does

Keep its responsibilities limited.

Model DOES:
understand schema semantics
explain data-quality problems
classify suspicious columns/values
suggest transformations
map old schema → new schema
explain pipeline failures
generate structured transformation plans
Model DOES NOT:
process the whole CSV
calculate millions of rows
replace Pandas
replace SQL
execute arbitrary Python
directly modify files

That separation is important.

4. Free tech stack

For V1:

Component	Technology
Language	Python
UI	Streamlit
Data processing	Pandas
Analytical SQL	DuckDB
File format	Parquet
Validation	Pydantic + custom rules
Storage	SQLite
LLM	OpenRouter
Model	Open 7–9B model
HTTP	httpx
Testing	pytest
Config	python-dotenv
Logging	Python logging
Version control	Git/GitHub

Everything can be free/local except the OpenRouter inference cost, depending on the model/provider you select.

For the first version, don't build around a specific model name. Configure it through:

OPENROUTER_API_KEY=your_key
OPENROUTER_MODEL=your_model

That lets you change between available open models without touching the application architecture.
